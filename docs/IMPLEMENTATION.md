## 腾讯企业邮 UIDVALIDITY 兼容修复（2026-09-30）

原收取流程只从 EXAMINE 响应取得 UIDVALIDITY，缺失时中止整个账号。现在按以下方式收取：

1. EXAMINE 返回有效的非零 UIDVALIDITY 时沿用增量收取。
2. 缺失时查询 `STATUS "<folder>" (UIDVALIDITY)`。imap 2.4 将 STATUS 属性交给 unsolicited response 队列，必须从本次查询对应的文件夹响应读取，不能只看返回的 Mailbox。
3. STATUS 被拒绝、仍缺失或为 0 时，每次重新下载并用完整原始 MIME 的 SHA-256 核对；来源键同时包含 UID 和内容哈希。不会使用假的 UIDVALIDITY，也不会仅凭旧 UID 跳过下载。
4. 网络中断或下载失败时保持此前来源状态；整文件夹成功后再对账。内容去重保证重试不产生重复存档，服务器 UID 重用时旧内容仍在本地。
5. 收件箱优先收取，错误包含文件夹名称。全量核对模式会记录日志，其代价是每轮重新下载。

新增 5 项协议回归测试使用真实 imap 库与模拟响应，覆盖 STATUS 恢复、正常增量/UIDVALIDITY 变化、缺失/0、UID 重用、重复下载、其他文件夹 STATUS 隔离和断线保留。协议依据：[RFC 9051 的 UID 与 UIDVALIDITY](https://www.rfc-editor.org/rfc/rfc9051.html#section-2.3.1.1)。


同轮真实收取还发现 RFC822.SIZE 元数据与完整 BODY[] 响应不一致。现在明确区分传输完整性和大小元数据：完整性由 IMAP literal 的 `{N}` 字节长度、FETCH 成功结束与完整 BODY[] 字段校验保证；部分响应（含偏移）、正文缺失、错误 UID、截断和解析失败均拒绝存档。RFC822.SIZE 差异只记录大小诊断，以实际完整 MIME 为准，仍需通过 MIME 解析、原子落盘和哈希验证。新增 2 项测试验证元数据差异时正文/附件精确还原，以及截断/部分正文/错误 UID 被拒绝。参考 [RFC 9051 §2.3.4](https://www.rfc-editor.org/rfc/rfc9051.html#section-2.3.4) 和 [literal 字节长度](https://www.rfc-editor.org/rfc/rfc9051.html#section-4.3)。


协议收取增加异常隔离。旧 IMAP 库对异常命令编号可能触发 panic；以前会使后台线程退出、任务互斥锁进入中毒状态，此后的收取错误被误报为“已有任务正在执行”。现在异常转为包含文件夹/步骤的可重试错误，关闭失败的连接、保留已下载存档，后台线程继续运行。新增测试模拟错误命令编号，检查任务锁可再次获取且后续正常同步仍能成功。

## 阅读布局调整（2026-09-30）

根据用户截图，将主卡片分为邮件列表和阅读区两栏，阅读区从卡片顶部开始；移除所有页面重复的面包屑标题，侧栏切换按钮与现有页面标题同行。“本地优先”和主题切换位于卡片外的应用右上角。阅读区采用紧凑的发件人、收件人、完整日期、标题顺序；操作图标、回复与转发紧凑排列在发件人信息右侧；整个邮件信息区固定，正文和附件独立滚动，保存状态仅在顶部标记，移除正文末尾的存档说明。外部图片直接加载，网页链接使用系统浏览器，mailto 链接打开应用内写信；正文按实际高度适配。

实际腾讯企业邮空文件夹返回 `STATUS … ()`，旧 IMAP 库要求 STATUS 至少包含一个属性而无法解析。现在先查询 UID，空文件夹直接完成来源对账，不查询无意义的 UIDVALIDITY。新增回归测试覆盖空文件夹响应，不影响已下载的 MIME 存档。

服务器在非空文件夹也可能返回空 STATUS 属性。`vendor/imap-proto` 保留上游 0.10.2 源码与双许可证，仅允许 STATUS 的属性列表为空；这样可读完命令结束响应并保持连接同步，随后使用完整 MIME 核对模式。新增测试验证非空文件夹的空 STATUS、继续 FETCH 与重复下载去重。

此前真实收取验证曾等待 macOS 钥匙串读取完成（线程采样停在 `auth::credentials → keyring::Entry::get_password`）。系统 SecurityAgent 界面不允许通过自动操作工具处理，需要用户完成系统授权；尚未宣称本次整轮同步成功。本轮只读核对已累计保存 320 封存档，完整同步是否成功仍需以收取日志为准。

## 写信、联系人与恢复流程（2026-09-30）

按首版清单补齐以下流程：

- **账号编辑**：沿用账号 ID，邮箱地址只读；支持名称、协议、服务器、端口、认证更新，空密码保留原凭据，可重新 OAuth 授权或改用收件密码发送。收发连接通过验证后保存。收件服务器或用户名变化时仅清除旧来源跟踪，不删除原始 MIME 或本地已读/分类状态。
- **全部回复**：从原始 MIME 解码 Reply-To/From/To/Cc，展开地址组、正确处理带逗号的姓名；优先 Reply-To，排除所有已配置的本人地址，跨 To/Cc 去重，不包含 Bcc。
- **通讯录**：本地联系人增删改查，发件人一键转为联系人；写信的 To/Cc/Bcc 从联系人及历史地址补全，支持键盘选择。手工保存的姓名优先于历史名称。
- **富文本**：Tiptap 支持加粗、斜体、下划线、列表、引用、链接及撤销；可切换纯文本，自动保存及恢复 HTML 草稿；SMTP 生成纯文本与 HTML 的 MIME alternative，附件独立保留。富文本代码按需加载。
- **筛选**：未读、星标、有附件可叠加；按标题、发件人、收件人、正文搜索，并与账号/分类范围共同生效，结果数量使用同一条件。
- **发送记录**：发送前持久化草稿及 MIME；明确区分服务器拒绝和结果未确认。启动时将中断的 sending 转为 uncertain，不自动发送；结果不明须确认重复风险后才能创建新 ID 草稿，仍需手动发送。SMTP 已确认但本地存档失败的记录可恢复本地副本。
- **备份恢复**：恢复邮件时同时合并规则及联系人；当前已有的规则 ID、联系人邮箱优先，旧版无联系人表的备份仍可使用；不恢复凭据、账户、草稿或发送队列。
- **后台检查与校验**：间隔持久保存为 1/5/10/15/30/60 分钟；每 10 秒检查一次调度，检测到循环暂停超过 45 秒或系统时间回退时补收，任务忙时保留补收请求。存档健康检查逐封验证 SHA-256、MIME 及附件解码，返回异常列表且不修改原件。这是时钟间隔检测，未实现 macOS 原生唤醒或网络恢复监听。
