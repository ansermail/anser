# 存档双级校验工作点（2026-11-04）

## 目标与范围

用户提供的 0.2.8 性能报告与另一版本截图涉及大体量存档。本轮先补齐与当前代码兼容的存档校验能力，不混入外置分层归档、7 天保留、“立即归档”或“取回本地”等独立迁移功能。

本轮目标：

- 分离完整原件与内置索引的统计口径。
- 提供快速校验与深度校验，二者都显示范围、进度和取消状态。
- 校验在后台线程运行，不阻塞阅读、写信和设置页。
- 结果持久化；应用退出或崩溃后不把未完成校验显示为成功。
- 外置存档盘不可达时明确报错，绝不回退到本机同名文件。
- 校验期间与存档迁移、删除互斥；不修改或删除任何邮件原件。

## 当前实现

新增 `src-tauri/src/archive_verification.rs`：

- 快速校验：原件存在、是普通文件、文件大小与索引一致。
- 深度校验：读取原件并核对 SHA-256，再解析 MIME、遍历叶子部分并解码附件。
- 后台线程执行；同一原件哈希在一轮内只完整读取一次，但仍按引用它的邮件逐封计数。
- 每 32 封及完成时发布进度；有界读取问题明细，最多保留 200 条，`problemCount` 保留全量数量。
- 同一存档根只允许一个校验实例；取消通过原子标记传递。
- 结果写入应用数据根的 `archive-verification.json`。启动时若发现 `running=true`，改为已取消并提示“上次校验未完成”。
- 校验全程持有 `Store::archive_gate` 的读锁及存档位置运行时的读锁，阻止迁移或删除在校验过程中移动文件；迁移仍使用既有“复制校验成功后切换”的写锁路径。
- 外置存档根由 `archive_location::physical_root` 解析；磁盘未连接或目录标识不符时直接返回错误。

新增命令：

- `archive_verification_status`
- `start_archive_verification`
- `cancel_archive_verification`

旧 `archive_health` 保留，改为同步执行一次深度校验，兼容既有调用与测试。

`ArchiveHealth` 增加：

- `mode`、`running`、`total`、`completed`、`cancelled`
- `startedAt`、`problemCount`、`error`

`Stats` 增加可选 `indexBytes`：

- 内置索引口径为 `mail.sqlite3`、`-wal`、`-shm`、`-journal` 当前文件大小之和。
- 原始邮件大小继续按完整保存的索引记录统计，不与 SQLite 文件混算。

设置页“本地存档”：

- 统计改为完整本地存档数量、原始邮件大小、内置索引大小三列。
- “校验存档”控件改为快速校验、深度校验、取消校验。
- 600 ms 轮询进度；显示模式、完成数量、取消状态、最近校验时间和问题详情。
- 初始状态读取完成前禁用校验按钮，避免慢状态响应覆盖刚开始的校验。
- 轮询与启动/取消请求使用序号防止迟到响应覆盖新状态。

双语文案位于 `src/locales/zh-CN.json` 与 `src/locales/en.json`，键和插值一致。
