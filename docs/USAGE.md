# 功能与使用说明

本文记录雁信当前功能的具体行为与使用边界。产品概览与下载安装入口见 [README](../README.md)，验收结果和待办见 [开发进度](DEVELOPMENT_STATUS.md)。

## 已接入

- 搜索索引子阶段当前在 `codex/search-scale` 开发分支，尚未进入正式 0.1.9：本地已有标题/发件人/收件人/正文建立派生全文候选索引，短词及不可完整索引的文本回退到精确检索；不自动下载在线正文，也不改变原始内容。真正后端分页、时间筛选和正文覆盖提示尚在继续开发。
- 邮件列表按实际时间从新到旧排列，不同时区会换算到同一时间基准；对话模式按当前范围内最新邮件排列，阅读对话时从旧到新。主题前的黑点表示未读（对话中存在未读邮件也显示）；邮箱名称前的彩色点仅表示所属账号，已读邮件也会保留。
- 含附件的邮件在列表底部信息行最右侧显示小回形针标识，与账号和分类信息分开。

- Gmail、Outlook、Microsoft 365、QQ、网易邮箱、腾讯企业邮箱、网易企业邮箱和自定义服务器入口；连接表单左上方的“返回其他邮箱”可返回服务商选择。
- 添加 QQ、Gmail、Outlook、网易账号时，地址栏默认显示常用邮箱后缀，只需填写账号部分；网易支持切换 `@163.com`、`@126.com`、`@yeah.net`。可直接粘贴完整地址，或选择“完整地址”输入其他域名。企业邮箱和自定义服务器仍填写完整地址，编辑已有账号时保留原地址。
- 过滤规则支持“复制到服务器文件夹”和“移动到服务器文件夹”：指定一个已启用的 IMAP 账号、来源目录和不同的目标目录，先预览匹配，再保存；保存后对新收取邮件生效，已有邮件需主动执行。界面使用中文目录名称，内部保留准确服务器路径。Gmail 标签动作暂未支持；正文条件可按需读取完整邮件后核对。
- “服务器规则执行记录”展示最近 50 次命中及关联任务的实际状态。命中与任务原子保存，重复扫描和重复执行同一配置不会重发 COPY/MOVE；修改条件、来源、目标或动作构成新配置。未入队的失败需主动“重新检查并入队”，关联任务则在设置的服务器文件夹操作中处理。结果不明不会自动重发；修改/停用/删除规则会取消仍未完成的规则处理链及其自有未提交任务；已经完成规则链创建的服务器任务继续在设置中处理，已提交或结果不明任务不会撤回。备份不包含这些待执行任务。源码回归已通过，规则触发真实服务端操作的端到端验收仍待补充。
- IMAP / POP3 收件、SMTP 发件、TLS / STARTTLS、密码/授权码、OAuth PKCE 代码路径。IMAP 支持 UIDVALIDITY 的 STATUS 兜底；完全缺失时逐封下载并按完整内容去重（每轮重下载）。
- 多账号收件箱、按标题/发件人/收件人/正文搜索、未读/星标/附件组合筛选、阅读、附件保存与 EML 导出；账号收取异常图标悬停或键盘聚焦可查看具体原因。
- 纯文本、富文本、Markdown 和 HTML 源码写信；支持导入 `.md` / `.html` 正文文件、效果预览、附件与 CC/BCC、草稿自动保存、回复/全部回复/转发。写信窗口默认放大，可最大化和还原。回复尊重 Reply-To，全部回复去重并排除已配置的本人地址；回复写入标准 In-Reply-To / References 引用头，转发附件仍需手动添加。
- 单封独立邮件使用普通阅读面板；存在回复引用关系时展示对话：来信靠左、自己的邮件靠右，时间从旧到新；底部快速回复、草稿保存与完整编辑。按回复引用链聚合，不按相同标题猜测；不同账号分开。
- 列表显示方式菜单，位于列表“全部 / 未读”右侧：可选择“按对话分组”或“逐封邮件”，选择会在本机记住。逐封模式只展示当前邮件，打开时只将当前邮件标记已读，批量操作只处理选择项。
- 正文工具栏支持上一封/下一封，快捷键为 ⌥↑/⌥↓。在已加载列表末尾点击“下一封”或按 ⌥↓ 会加载后续结果并继续阅读；未读邮件打开后移出列表，也可继续向后阅读。加载失败保留当前正文，可再次尝试；切换账号、筛选或显示方式会取消旧导航，输入和弹窗不会被导航快捷键打断。前端累计最多 5000 条，仍非真正的后端分页。
- 添加或编辑账号时可切换“收到的邮件保存在本地”，默认开启。关闭后只保存列表元数据，打开正文时从服务器读取，不持久保存收到的正文或附件；已有完整存档保留，重新开启后逐封补存。应用自己发送且 SMTP 已确认的邮件仍保存本地副本，供发送恢复和往来记录使用。
- 点击账号旁的箭头展开服务器文件夹，按服务器返回的分隔符显示父子目录，子目录只显示自身名称；点击可信文件夹显示该文件夹邮件并补收；已隔离目录显示原因，不自动补收。支持 IMAP 中文文件夹；POP3 只有收件箱。用户已读/星标及撤销已接入持久出站同步队列；每轮批量回读服务器标记，已缓存正文不重复下载，保护未完成的本地意图与规则标记。设置页可查看任务与失败原因并重试。服务器单封 MOVE 已实现；映射目录的归档/垃圾邮件/服务器废纸篓快捷入口已实现，永久删除尚未实现；其他客户端改标记的真实端到端验收仍待补充。异常根目录有持久来源隔离与独立只读核查：设置 → 目录来源检查可查看原因和旧来源数量。隔离不会删除元数据、MIME 或附件；仅依赖异常来源的在线条目暂停展示，完整本地存档保留。核查成功后仍须完整收取重新核对，才能恢复旧来源。腾讯/QQ旧在线来源准确归属及根目录写入兼容仍待解决，不能把收件箱成功等同于全目录成功。
- 本地通讯录、从邮件创建联系人、收件人地址自动补全；常用地址同时来自已保存邮件。
- 编辑账号名称、收发服务器及认证配置；收、发连接验证成功后保存，邮箱身份保持不变，已有邮件与本地操作状态保留。
- 兼容声明 GBK/GB18030 等字符集的旧式原始邮件头；保留 HTML 邮件的排版样式，列表摘要不包含样式代码。已有存档在启动时从本地原件更新显示信息。
- 邮件时间使用原始 Date，缺失或无效时依次尝试 Received 和 IMAP INTERNALDATE，不使用下载时间。旧存档自动修复显示日期；没有可用日期显示“时间未知”，待服务器连接成功后补充。
- 大邮箱列表只传送元数据和当前分页，会话关系按索引版本缓存；正文按需读取，后台收取合并界面刷新，避免反复加载整个邮箱正文。
- 可配置规则：账号范围、多条件 AND / OR、优先级、命中后停止、预览、对历史邮件执行；归类、已读、星标和废纸篓动作只作用于本地。
- 完整原始 MIME 邮件独立留存；存档以 SHA-256 命名，读取时校验，先持久化再归类。服务端清理或移除账号不会删除已完整下载的原始邮件。
- SQLite 索引、存档备份/恢复、macOS 钥匙串保存凭据、菜单栏入口；支持 IMAP IDLE 实时监听收件箱，收到通知后立即排队收取该账号的收件箱，各账号独立执行，遵循账号的本地留存设置。手动收取优先检查各收件箱；选中服务器文件夹时刷新该文件夹，同一文件夹的任务按顺序执行。历史文件夹同步不会占住其他文件夹或账号的收件箱。后台补查可设为 1/5/10/15/30/60 分钟，覆盖 POP3、不支持 IDLE 的服务器及其他文件夹。断线自动重连，暂停/移除/编辑账号后更新监听；检测到睡眠间隔后重新连接并补收，真实睡眠唤醒仍待验收。
- 批量校验本地原始 MIME 的哈希与附件解码，列出缺失或损坏的存档；不会修改或删除原件。
- 设置中可按账号或全部删除本地存档，确认前显示数量、大小及仅有本地来源的邮件数量。保留可在线读取的列表索引，移除仅本地记录；可同时关闭后续自动保存。共享原件仍被其他账号使用时保留；失败或中断时恢复仍被索引引用的文件。发送记录、草稿、已导出备份和独立下载文件不在此清理范围。
- 发送记录显示 SMTP 确认、服务器拒绝和结果未确认；支持手动准备重发草稿及恢复已发送邮件的本地副本。客户端还会为新 IMAP 发送安排服务器已发送副本，并单独显示保存结果：未提交失败可以重试保存，结果不明只能只读核对，均不会重新发送 SMTP；历史记录需主动安排。POP3 保持本地副本语义。
- 系统通知：新邮件和发送结果分别开关，普通发送、快速回复和定时发送覆盖成功/失败/结果未确认；首次导入和 24 小时前的历史邮件不通知。设置提供测试通知按钮；macOS 通知权限、专注模式和横幅由系统控制。
- 开机自启：正式应用可通过设置注册 macOS LaunchAgent，登录后后台启动；开发预览依赖 Vite，禁用开启入口以免登录后空白窗口，允许关闭已有启动项。
- 本机定时发送：计划持久保存，正文和附件在安排时固定；可修改时间、取消并恢复草稿。结果不明时不自动重发。
- HTML 邮件直接显示外部图片，旧 HTTP 图片及字体资源升级为 HTTPS；资源服务器已删除或拒绝访问的内容无法加载。网页链接在系统浏览器打开，mailto 链接进入本应用写信窗口；清洗脚本和表单，正文沙箱禁止脚本运行。阅读区采用紧凑地址、标题布局，回复与转发位于顶部，列表及阅读时间显示完整年月日与时分秒；附件卡片显示文件名、大小和下载图标，随栏宽排列。

## 写信与定时发送

正文格式菜单支持纯文本、富文本、Markdown 和 HTML 源码。Markdown 会转换为 HTML 邮件，支持标题、列表、表格和代码块；HTML 可直接粘贴完整文档或片段，或点击“导入文件”。两种源码模式都有预览，草稿保留原始源码；发送时附带可读的纯文本备用正文。HTML 保留内嵌样式和表格，脚本及表单会被清理；正文文件导入上限 10 MB。

回复默认不包含原文，转发默认包含原文；可用“包含原文”开关调整。原文在编辑区域下方独立渲染，保留 HTML 样式、表格及图片，不进入富文本编辑器。点击“发送预览”查看新写内容与原文合并后的正文。发送时内嵌图片生成 MIME inline 附件，草稿和取消定时计划保留原文及开关状态；不同收件客户端可能调整 HTML 展示。

点击“定时发送”，选择本机时区的日期与时间并确认；在“发送记录”中修改时间或取消计划。取消后正文及附件恢复成新草稿，已有计划记录保留。

定时发送由本机后台执行，**需要应用运行、Mac 醒着且能连接 SMTP**；关闭窗口仍可执行，完全退出或睡眠时无法发送。错过不超过 5 分钟的计划可在恢复运行后执行，超过 5 分钟标记为“已错过时间”，需重新安排。账号暂停/移除、认证失败、服务器拒绝或结果不明均保留记录；不会反复自动重试。发送使用独立任务锁，不再等待整轮邮件收取；普通发送与定时发送仍按顺序执行，防止重复投递。发送计划暂不包含在存档备份中，也没有云端定时服务。

## 连接真实邮箱前

QQ、网易等通常需在邮箱官网启用 IMAP/POP3/SMTP 并获取授权码。企业服务器配置及权限取决于管理员；这些预设尚未逐服务商联调。

Gmail / Microsoft 的 OAuth 需要注册属于本产品的应用。可以在账号高级设置填写 Client ID，或构建前设置 `MAIL_GOOGLE_CLIENT_ID`、`MAIL_MICROSOFT_CLIENT_ID`；Google 桌面应用如需 client secret，可设置 `MAIL_GOOGLE_CLIENT_SECRET`。不要提交实际凭据。原生应用中的 client secret 不是可保密的服务端秘密。

本机开发可在项目根目录的 `.env.local` 填写上述变量；`npm run desktop` 和 `npm run desktop:build` 会加载，已有进程环境变量优先。该文件已被 Git 忽略，建议权限设为 `600`，不要使用 `VITE_` 前缀暴露到前端。修改后需要重新启动开发应用，让 Rust 重新编译配置。添加账号时选择 Gmail、填写邮箱地址，OAuth Client ID 留空即可使用本机默认配置，再点击连接并在系统浏览器完成 Google 授权。Google 控制台处于测试状态时，需要将登录账号加入测试用户；实际登录与收发仍需验收。本机配置不会自动进入 GitHub 发布流水线；组织仓库通过同名 GitHub Secrets 单独配置 Google Client ID / Secret，在下一次双架构构建中生效，已发布安装包不变。换 Client 后，原客户端签发的令牌不能直接迁到新客户端，已有 Gmail 账号如刷新授权失败需重新连接授权；高级设置手填的 Client ID 优先于构建默认值，应与新客户端配置一致。

代码使用系统浏览器、PKCE 和本机临时端口回调；Google 应配置桌面客户端，Microsoft 应配置公共原生客户端与 localhost 重定向及邮件委托权限。OAuth 应用发布审核、租户策略和真实授权仍需验证。参考 [Google 原生应用 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)、[Microsoft 邮件协议 OAuth](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth)。

Microsoft 应用注册支持“任何 Entra ID 租户 + 个人 Microsoft 账户”，回调在“移动和桌面应用程序”平台填写 `http://localhost/callback`；运行时的随机端口由微软 localhost 匹配规则处理，路径必须一致。当前授权码 + PKCE 流无需客户端密钥，也无需启用用于其他无回调场景的“允许公共客户端流”开关。委托权限声明包含 `IMAP.AccessAsUser.All`、`POP.AccessAsUser.All`、`SMTP.Send` 和 `offline_access`；部分目录的控制台通过 Microsoft Graph 入口提供这些权限。雁信的协议授权仍使用完整 `https://outlook.office.com/` scope，不能改为 Graph 资源令牌来连接 IMAP/SMTP。连接时填写实际的 Outlook.com / Microsoft 365 邮箱地址，Azure 管理账号的登录地址不一定有微软邮箱。

2026-10-10 已建立 Anser 的微软公共桌面客户端，并将 Client ID 保存于本机忽略配置和组织仓库 Secret `MAIL_MICROSOFT_CLIENT_ID`。双架构 Release 在原生构建前检查并注入配置；本机需重新编译或在高级设置填写 Client ID 才能让现有进程使用。应用注册及权限声明完成不代表邮箱授权、令牌刷新、真实收发或发布者验证完成；企业租户策略仍可能要求管理员批准。

当前开发版会分别显示等待浏览器授权、交换令牌、收件及发件服务器验证；等待浏览器时可取消，超过 3 分钟会结束等待。请完成新打开页面的授权，过期页面不能用于下一次连接。Google 使用 `127.0.0.1` 回环回调及随机端口，桌面客户端无需在控制台逐个登记临时端口。Gmail 本机授权、令牌交换和连接验证已通过，实际发信、长期令牌刷新及标签操作仍需验收。

## 数据与行为

- IMAP 实时连接优先监听 IDLE，同时每分钟轻量检查一次目录变化；未变化不额外下载原件。记录会区分主动推送、实时连接补查和用户设置的定时补查。服务器延迟投递或未及时报告变化时，不能保证瞬间收到。
- QQ 报告邮件已由 SMTP 保存时，应用只读核对服务器既有副本，不重新发信或重复上传。有限次核对仍未确认时，可在发送记录选择“只读核对副本”；存在绑定目录的其他拒绝记录也提供该入口。只有唯一副本与完整内容核对通过才显示已核对成功。

- 收件箱历史下载时收到新的实时通知，当前只读下载会让出，新一轮优先收最新邮件。未完整传输的邮件下轮重取，旧存档和来源保留；活动中的“本轮结束”不表示所有历史原件已下载。其他账号、SMTP 发送及服务器复制/移动不受此下载中断影响。

- 新建空白邮件不会自动保存草稿，关闭时直接舍弃；默认发件账号和自动附加的签名不算已填写内容。填写收件人、抄送/密送、主题、正文或添加附件后正常保存；回复/引用上下文保留。空白邮件显示“空白邮件不会保存”，有内容的草稿仍自动保存。

### 邮件签名（0.1.6 起）

在「设置与账号 → 邮件签名」的卡片顶部选择发件账号，打开启用开关后展开配置，填写文字或勾选「使用 HTML」。也可导入文本、HTML、PNG、JPEG、GIF 或 WebP 文件（最多 2 MB），导入的是文件内容，移动原文件不会影响签名。保存后，新邮件、回复和转发使用该账号的签名。

顶部开关直接保存所选账号的启用状态；关闭后保留已有签名，账号选择仍可使用。展开后左侧管理 HTML 开关、文件与保存，右侧编辑内容；内容修改需点击「保存签名」，开关操作不会误存尚未保存的编辑。启用 HTML 或导入 HTML/图片时，右侧分为编辑与实时预览，两侧框体等高并对齐；导入的纯文本另显示只读内容。内容区较窄时预览排在编辑下方，避免两边被挤窄。

完整性检查位于上方存档统计卡片的原始邮件大小后，显示检查进度、结果和异常；系统通知与启动、后台检查在邮件签名上方。完整保存任务、目录来源检查和其他服务器任务/最近活动默认折叠。页面底部依次为关于与更新、后台收取说明、开发版示例入口；项目仓库链接使用系统默认浏览器打开。

设置页按账号、存档、应用偏好、后台任务与活动、关于说明分组。同组卡片保持统一间距，组之间增加留白并用横向分割线区分。

写信时可在底部工具栏「定时发送」后关闭「附加邮件签名」；签名预览显示在编辑正文之后、引用原文之前。HTML 和图片签名会生成 HTML 邮件及纯文本替代正文，图片作为内嵌附件发送。签名随草稿保存，修改账号默认签名不会改写已有草稿；切换发件账号会读取对应账号的签名。读取失败时可以重试，或明确选择本封不使用签名。

### 存档保存位置（0.1.6 起）

在「设置与账号」上方显示存档数量和大小的「完整保存，独立留存」卡片中，点击「修改存档位置」选择磁盘或文件夹；当前路径、打开位置及迁移提示也在这张卡片内。应用使用所选位置的 `Anser-Archive/archive` 保存完整邮件原件（含正文与附件）。先复制并校验所有原件，再切换路径并清理原位置已迁移的文件；途中不要退出应用或拔出磁盘。可以取消选择，也可以连接磁盘后选择「恢复默认位置」。账号、钥匙串凭据、SQLite 索引和设置仍保存在本机原目录。

存档磁盘断开时，列表索引仍可查看，完整原件读取、保存及备份会报明磁盘不可用，不会自动改存到本机。重新接入后刷新存档位置。路径切换后如果原位置清理未完成，可连接相关磁盘并点击「继续清理原位置」。已有其他 Anser 存档的目录不会被直接覆盖。

服务器状态同步、完整保存任务、目录来源检查、服务器文件夹操作和最近活动默认折叠，点击右侧箭头展开；关于与更新提供项目仓库链接。正式桌面包隐藏示例邮箱入口，开发预览保留。独立网页预览仅使用虚构数据，可阅读、搜索、切换主题和调整分栏，不连接邮箱或发送消息。

### 保存范围与磁盘预算（0.1.7 起）

在账号操作的“文件夹保存范围”中调整选择后，可点击“检查服务器数量与空间”。检查使用当前未保存的选择，读取服务器邮件编号与大小，不下载正文、修改标记或保存范围；显示所选范围的服务器邮件位置、尚未缓存位置、预计待保存数，以及实际存档磁盘的可用空间。

预算按服务器报告的原件大小和本机完整保存记录计算，额外预留 10% 与 128 MB；多个目录的同一邮件可能重复计入，服务器未提供稳定编号时按全部原件估算。数量是检查时的快照，不是已完整下载的证明；可用空间不代表目录可写或原件通过完整性校验。无保存范围时预算为零；尚未发现目录、目录异常、大小缺失或检查期间编号变化时明确显示未知，不视为无需保存。检查最长 90 秒，可取消；关闭、切换账号或修改范围会取消并废弃旧结果。

IMAP 仅使用只读目录与大小查询，POP3 核对 UIDL/LIST；不发送正文取回或服务器删除命令。外置存档断盘、标识不符或迁移中不给本机替代空间；调整存档位置后需重新检查。演示与 Pages 不连接真实服务器或读取磁盘。新账号实际范围下载、大附件/断网/外置盘故障矩阵仍在验收中。

### 打开 EML 邮件文件（0.1.6 起）

在 Finder 中右键 `.eml` 文件，选择「打开方式 → Anser（雁信）」；要设为默认应用，可在「显示简介 → 打开方式」选择 Anser，再点击「全部更改」。应用内不提供额外的「打开 EML」按钮。支持查看发件人、收件人、抄送、原始日期、纯文本/HTML 正文和附件；附件可调用本地应用预览或另存为。文件只读查看，不自动加入账号、列表或存档；原件不会被改写，附件另存也不能覆盖正在阅读的 EML。当前单文件上限为 64 MB，损坏内容会给出错误或解析警告；多份文件按队列查看。

安装 0.1.6 或更新版本后，设置默认打开方式：Finder 选中任意 `.eml` → `⌘I`「显示简介」→「打开方式」选择「雁信」→「全部更改」。也可右键「打开方式 → 其他」选择应用，仅打开本次文件。雁信提供文件关联声明，不自动更改现有默认应用。GitHub 0.1.6 已提供此功能；`npm run desktop` 也可测试开发版。

### 网页预览与自动更新

[GitHub Pages](https://ansermail.github.io/anser/) 直接复用桌面主界面与业务组件。`main` 中相关界面、样式或预览构建修改会自动触发 Preview Pages 流水线，无需再维护独立页面；流水线完成后刷新网页即可。桌面原生功能仍需客户端及独立桌面版本发布。

网页固定为虚构示例数据，只演示阅读、筛选、布局、主题及设置界面。账号连接、发信、定时发送和本机文件/通知操作不可用；示例数据保存在本页内存，刷新会重新初始化。不会读取已有桌面账号或浏览器中的邮箱示例持久数据。

### 本机数据

- 默认数据目录由 Tauri `app_data_dir` 决定，macOS 通常为 `~/Library/Application Support/dev.maildesk.desktop/`；应用设置页显示实际位置。
- `archive/*.eml` 保存已完整留存的原始 MIME，SQLite 保存列表索引和本地操作状态；在线阅读账号不写入收到的 MIME 文件，元数据仍在本机。文件本身尚未做应用层加密。
- 只修改账号名称或本地留存开关时直接“保存设置”，无需等待收取结束或重新验证服务器。后台收取读取最新留存设置，同步结束不会覆盖开关；已有完整存档保留。修改服务器或凭据仍需验证。
- 关闭窗口保留后台运行；点击菜单栏图标直接显示并聚焦主窗口，不弹出二级菜单。关闭窗口后点击 Dock 图标也会重新显示，最小化的窗口会恢复。退出使用应用菜单或 ⌘Q。退出 App、Mac 睡眠或断网时不能继续下载。**必须在服务端删除前完成下载**，才能保留本地副本。
- 主窗口记忆尺寸、位置与最大化状态，关闭时保存，启动时恢复；不持久化隐藏、最小化或 macOS 原生全屏状态。服务器文件夹使用普通/扩展 LIST 特殊用途标记或常见精确名称显示中文标签与图标，实际服务器路径保持原样；设置中的账号操作支持自定义特殊文件夹映射与恢复自动识别。
- 备份包含邮件、存档元数据、规则和本地联系人，不包含凭据、账号、草稿、待发队列或服务端操作队列。恢复时合并缺失的规则和联系人，保留已有同 ID 的规则及同邮箱的联系人；不恢复服务端文件夹关系。兼容没有联系人表的旧备份。
- 发送前在界面等待 8 秒，可取消；进入 SMTP 阶段后不能撤回。失败不自动重发。应用中断时未完成的发送记录转为“结果未确认”；准备重发必须先确认重复发送风险，只创建草稿，仍需手动点击发送。
- IMAP 阅读工具栏的复制/移动使用 shadcn 下拉菜单：来源自动固定，选择目标即记录任务。移动菜单提供归档、垃圾邮件、服务器废纸篓快捷项，缺失或冲突的映射显示禁用说明；All 不视为归档。设置页“服务器文件夹操作”显示持久任务；提交前检查 UIDPLUS/IMAP4rev2，保存 COPYUID 并核对目标全文后才标记完成。已提交但确认丢失不自动重发；已保存回执的原生 COPY/MOVE 失败任务仅重试只读核对。COPY 保留原邮件；原生 MOVE 要求服务器能力及可靠的来源 UIDVALIDITY，核对目标全文和原编号已移除后才更新来源，本地完整存档保留。移动中的已读/星标修改会提示等待；未完成标记任务需先处理。MOVE 即使返回拒绝也可能部分成功，无可靠回执时不重发：先刷新目标目录，在设置中点击“只读核对”，仅唯一可信目标、全文匹配及原编号消失都通过才完成。目标有多个匹配副本或命名空间变化继续保留未确认；不执行普通 EXPUNGE/CLOSE。服务器无 MOVE 但有 UIDPLUS 时，分阶段复制并保存回执、核验目标和来源全文，然后只标记/移除精确 UID。移除中断后只读核对，主动选择“继续移除原目录”会重新核验两个副本，不会再次复制。无 UIDPLUS 时拒绝提交。永久删除尚未实现。
- 当前没有云端处理、遥测或自动上传。用户已允许后续设计云端能力。

## UI 组件规则

所有界面组件统一使用 **shadcn/ui**。新增功能通过组合官方组件完成，不再自行实现基础控件；具体要求见 [AGENTS.md](../AGENTS.md)。定时发送使用中文 Calendar + Popover 日历和 Select 小时/分钟选择，写信和发送记录的修改时间共用同一个选择器。自动补全使用 Command + Popover，已读/未读切换使用 Tabs，账号勾选使用 Checkbox。

`npm run check:ui` 检查业务代码中的原生控件、自绘按钮入口和原生日期/时间选择器，`npm run build` 会先执行该检查。`src/components/ui/` 保留官方组件源码及必要适配。

### 编码异常与发送回执

部分历史邮件的 MIME Base64 内容可能不规范。兼容 URL-safe 字母和缺失填充，但不删除任意非法字符；无法解码的正文片段、内嵌图片或附件单独标记，继续收取其他邮件。本地留存账号保留完整原始 MIME，异常附件禁止下载伪造或空文件；存档校验仍报告这些异常。

发送记录区分“发送成功 · SMTP 已确认”“发送失败”和“结果未确认”。成功表示发送服务器已接受，不证明最终送达或对方已读；断线而未获确认时不自动重发。此版本不请求阅读回执。

### 附件预览

点击附件名称或文件图标，雁信会将附件解码到应用专用缓存，并调用 macOS 默认应用打开，无需选择下载位置。右侧下载图标用于另存附件。普通单封与回复对话均支持，打开过程中显示加载状态并防止重复点击。

预览缓存与原始邮件存档独立，按邮件内容和 MIME 片段隔离；7 天未使用的缓存会在下次预览时清理。关闭账号的本地留存后，预览仍需临时取回附件，但不会因此将邮件加入本地存档。附件损坏会显示错误；程序或脚本不直接启动，可自行另存。

## 本地开发与签名

需要 Node.js 22.15 或更新版本、Rust stable、Xcode Command Line Tools；本轮在 arm64 macOS 上验证。

```sh
npm ci
npm run desktop
```

`npm run desktop` 会启动 Vite 并直接打开 macOS 开发版，支持真实邮箱与本地存档，无需打包或安装。保持命令运行，前端修改自动刷新，Rust 修改自动重新编译并启动；按 Ctrl+C 停止。日常界面调整和联调使用此命令，交付应用时再运行 `npm run desktop:build`。

开发启动器使用 execve 交接进程，Rust 重新构建会结束旧实例，不会累积 Dock 图标。应用采用单实例保护，再次启动只打开已有窗口。

macOS 开发启动器在启动前用本机唯一有效的 Apple Development 证书签名，固定使用 `dev.maildesk.desktop` 应用标识，避免临时签名随重建变化而反复请求钥匙串授权。切换签名后的首次读取现有凭据可能仍需在系统提示中选择“始终允许”；系统钥匙串被锁定或更换签名证书时仍可能要求授权。已有账号、钥匙串服务名及本地存档保持不变。

若本机没有开发证书，在 Xcode 的账号管理中创建 Apple Development 证书；若有多个证书，通过 `YANXIN_DEV_SIGNING_IDENTITY` 指定有效证书的完整名称或 SHA-1，例如 `YANXIN_DEV_SIGNING_IDENTITY='<证书 SHA-1>' npm run desktop`。签名失败会停止启动，不会退回临时签名。`npm run test:desktop` 验证签名选择与失败处理。此处仅为本机开发签名，正式分发的 Developer ID 签名与公证仍待配置。

只预览界面：`npm run dev`，访问 `http://127.0.0.1:1420`。浏览器不支持真实邮件收发，点击“先体验一下”加载演示账号和示例邮件。

```sh
npm test
npm run test:rust
npm run desktop:build
```

桌面产物：`src-tauri/target/release/bundle/macos/雁信.app` 及带更新签名的 `.app.tar.gz`/`.sig`。本机发布脚本从仓库外读取匹配的更新密钥，密钥缺失或不匹配会停止构建。Developer ID 分发签名及公证尚未配置。

### 服务器已发送副本

使用账号文件夹设置中唯一有效的“已发送”目录；找不到或目录被隔离时保留任务和本地副本，修复映射后可重试。服务器已有一致副本时直接核对，不重复上传；确认丢失后不会自动重传。QQ 自动保存若改写 Message-ID，只有完整 MIME 和原始邮件头的唯一匹配才建立关联，回复保留已核实的服务器标识。多个候选或内容不同会要求处理。

副本保存失败不改变“SMTP 已确认”的发送结果，也不证明收件人送达或阅读；发送记录继续保留原件。大附件、其他服务商和弱网等真实上传矩阵仍在完善。

协议参考：[UIDPLUS 回执与只读发现](https://www.rfc-editor.org/rfc/rfc4315.html#section-3)、[multipart epilogue 语义](https://datatracker.ietf.org/doc/html/rfc2046#section-5.1.1)。实现仅兼容观察到的空白 epilogue，不忽略正文或附件变化。

## 文件夹保存范围

在「设置与账号 → 账号操作 → 文件夹保存范围」为 IMAP 目录选择跟随账号、完整保存或在线阅读。账号的本地留存开关是默认值；明确设置的目录会覆盖该默认值。在线阅读仅缓存列表信息，查看正文/附件时临时取回；已有完整存档不会因切换为在线阅读而删除。POP3 仍使用账号保存开关。

垃圾邮件和服务器废纸篓默认不自动收取；明确设为完整保存才纳入后台收取。开启目录完整保存后，下次该目录收取会补齐仍在服务器上的历史正文和附件；已被删除且未下载过的内容不能恢复。异常来源仍需通过目录核查。客户端提供单封/批量手动补存与持久任务。

修改来源服务器配置或移除账号会清除文件夹覆盖；删除本地存档时若选择停止保存，也会清除对应覆盖。备份不包含账号或服务器保存范围，恢复不会重新启动整目录下载。

## 手动完整补存

在线邮件阅读面板点击“完整保存到本地”；会话内菜单可保存该封邮件，多选工具栏可以批量保存。按对话分组时包含选中对话的各封邮件，逐封模式只保存选项。此操作不改变账号或文件夹的自动保存设置，已有标记、日期、本地归类与来源保留，不自动重跑规则。

在设置或存档管理查看“完整保存任务”：排队、下载与校验、完整保存、失败、暂停或取消分别展示。关闭窗口继续处理；退出应用后，下次打开从持久任务恢复。暂停/取消阻止在途结果发布，取消不会删除已保存原件；失败时重新检查并保存，重试会重新读取完整邮件。来源已失效/隔离、编号存在歧义或本地记录冲突时显示原因，无法恢复服务器已删除且从未保存的正文。

任务不进入备份；移除账号、删除本地存档并选择停止保存时，相关未完成任务取消。大附件及断网、睡眠、磁盘不足的真实矩阵仍待验收。文件附件和内嵌图片以 Base64 传输，避免 SMTP 规范化换行改变文件字节。

## 收件延迟诊断

收到服务器的新邮件通知后，应用会先检查新邮件并更新列表，再回读旧邮件的已读/星标。设置与账号的“最近活动”中，“收件诊断”会显示本轮由实时通知、连接后补查还是定时补查触发，以及排队、连接和目录等待耗时。整轮结束前，已下载的新邮件就可以阅读；整轮耗时包含旧邮件状态检查，不能直接当作新邮件的到达延迟。

2026-10-09 两个授权测试账号互发，SMTP 成功到自动入库分别约 2.8 秒和 7.5 秒，正文正常，期间没有手动刷新或重启。这是本次网络与账号的结果，其他服务商、睡眠/断网和繁忙收取时的延迟还在验收中。同一目录已有任务时仍按顺序处理，错误或断线会自动重连并保留定时补查。

旧邮件状态回读期间又收到新通知时，应用会让剩余的旧标记/日期检查先暂停，下一轮先检查新邮件；最近活动会说明“旧邮件状态回读让出收件箱”。已有邮件来源保留，旧状态稍后补查。正在传输的单个请求和大附件仍需等待传输结束或超时，繁忙收取与睡眠/断网场景还在验收中。

## 连接后保存引导与状态

新增邮箱验证成功后会展示保存引导，可调整 IMAP 文件夹范围，也可选择“以后再设置”，使用连接时选择的账号默认方式。保存位置可直接打开。已有账号在“设置与账号 → 账号操作 → 文件夹保存范围”查看；POP3 入口为“本地保存设置”，不提供服务器文件夹选择。

保存状态显示已缓存、完整保存、范围内待保存、失败补存任务及最近成功收取时间，每 5 秒更新。待保存按已保存的范围设置统计；编辑但尚未提交的范围不改变数字。尚未发现的服务器历史邮件不包含在内，0 待保存不代表整个服务器已保存；异常来源须先核查。完整性校验仍由“校验存档”执行。

可以填写服务器保留期（1–3650 天，未知留空），在待保存邮件接近所填期限时提醒。这个值不修改邮箱服务器的删除规则，也不能恢复从未下载且已删除的正文或附件。POP3 可保存保留期，但保存范围始终跟随账号默认设置。

## 完整保存与在线正文规则（RULES-03，2026-10-10）

- 新增“完整保存到本地”和“完整保存并归入本地文件夹”。命中后保存原始 MIME 正文与附件；不改变账号/文件夹的默认保存范围。保存并归类只在原件保存成功后执行，保留邮件 ID、日期、已读/星标和服务器来源。
- 预览不下载、不执行动作；已知主题/账号先筛选。未知正文或附件结构标为“等待正文核对”，不能据此认定“不包含”或“无附件”条件命中。
- 点击“对已有邮件执行”或新收取命中需要读取/保存的链后，在过滤规则页的“规则处理任务”查看进度。默认折叠，最近 100 项；正文只临时读取，未命中保存动作时不保存在线正文或原件。
- 核对、保存、来源隔离或服务器动作入队失败会停止后续规则。可暂停、继续、取消剩余规则，或修复问题后重新核对；重新核对从当前字段状态执行剩余步骤。已经保存的原件与已完成步骤保留，取消不是撤销已完成的分类。
- 链中的服务器复制/移动等全部步骤完成后才提交。服务器任务提交后实际结果仍看“服务器规则执行记录”和设置的文件夹操作；结果不明不会自动重发。关联规则链阻塞时，在规则处理任务重试，不能从执行记录提前提交服务器动作。
- 示例/Pages 只对已有虚构完整邮件演示分类，拒绝真实下载和异步任务。此阶段已在开发预览验证；公开 0.1.6 桌面包尚不包含 RULES-03。
