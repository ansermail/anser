本轮用真实 Soniox 邮件复测发现页脚文字为 571 字，未进入原 320 字品牌区限制。现为带紧凑图片的多行品牌页脚单独放宽到 1200 字；本机 0.1.43 arm64 实包在深色下可见完整 `#f4f4f4` 圆角底板和黑色字标。

第二轮复验另确认线程列表连续按 Backspace 可令 WebKit 导航到空白文档。现在非编辑控件的 Backspace 在捕获阶段被取消，编辑正文与输入控件不受影响，并为主应用和外部邮件窗口增加顶层 React 错误边界。自动回归分别覆盖非编辑区/输入框行为与渲染异常后的双语重新加载界面。

用户在后续原生复核中确认附件卡片的整行铺满与默认图标问题。现改为内容自适应紧凑卡片，PNG/JPEG/GIF/WebP 在卡片左侧显示真实小缩略图，后端按字节和尺寸预算生成 data URL，其他格式或失败回退类型图标。真实 ArcZip 邮件的 `logo-188.png` 已在 macOS arm64 实包只读复测，卡片恢复紧凑宽度且显示真实图片。

用户继续指出缩略图四角仍是直角，透明 PNG 被显示成灰色方块。根因是样式引用了不存在的 `--radius`，并在缩略图下铺了 `var(--muted)`。现改用现有 `--radius-md` 的 8px 圆角，移除外层灰底并让图片圆角继承容器，透明区域直接显示附件卡片背景。重建后的 macOS arm64 实包已重新打开 ArcZip 邮件，`logo-188.png` 保持透明背景和原始灰、紫、橙配色，不再出现灰色方块。

定时发送已从正文内的占高区域移至底部操作栏上方的 shadcn Popover，macOS 实包确认面板覆盖正文但打开前后编辑区高度不变；复测取消未创建计划。写信表格菜单在 WebView 中原先底部项不可达，现把非表格状态的操作组排成两列并限制到窗口可用高度；实包分别核对插入网格及插入 2×3 表格后的上下文菜单，行列、合并、表头、尺寸、重置和删除入口全部直接可见，无裁切。

文件夹保存范围把“服务器保留期”数字输入移到标题和说明右侧同一行。特殊文件夹改为用途、目录选择、第三列识别结果；Gmail 的长 `[Gmail]/…` 路径保持在第三列单行省略，未识别的归档用途也在同行说明。两项均已在 macOS arm64 实包核对，关闭弹窗未保存修改。

定时发送的小时和分钟原为 24/60 项下拉列表，用户要求改为滚轮或直接输入。现用 shadcn `InputGroup` 组合两位数字框和紧凑上下按钮，支持直接输入、键盘上下键、聚焦后滚轮及按钮调节；小时和分钟分别限制为 00–23、00–59，回车或失焦补零并拒绝越界值。用户随后指出箭头太靠右，已将调节组向数字侧收拢并保留右侧呼吸空间。未来时间约束按用户复核改为静默限制：早于今天的日期由 Calendar 禁用，当天输入从下一分钟起有效，越界输入恢复、按钮停在边界，等待到计划时间过期后自动推进，不再显示红色错误行。macOS arm64 实包核对 11 月 16–21 日按钮禁用和当天过去时分自动回到有效值，取消未创建计划。

收件人、抄送和密送任一组超过 3 个地址时都会在行内显示 `+N`，点击后在原字段展开完整列表并自然换行，按钮切换为“收起”；阅读、对话和外部邮件窗口共用。macOS arm64 实包只读打开含 24 个抄送的 MVNE 邮件，核对行内 `+21`、完整地址展开及收起。写信表格菜单同步改为固定 20px 方格、4px 间距和内容宽度，行列操作保留两列，尺寸、重置与删除在底部整行展示；macOS arm64 实包已核对菜单整体明显收窄且右侧不再留大片空白。最新完整前端回归 77 个文件 601 项通过，UI、1,863 条双语键、TypeScript、生产构建、本地桌面包及格式检查通过。
