## 统一模型配置

- 在既有「阅读与写信」分类内改造翻译设置卡。模型配置与翻译偏好集中在同一张「AI 智能助手」卡片，采用左侧说明、右侧控件的单列响应式布局，窄区自动上下排列。
- 复用现有 OpenAI 兼容配置、加密凭据、端点检查和代理路径，避免要求已配置用户重新输入 Key。首期可沿用 SQLite 键 `translation` 与密钥标识 `translation-api-key`，命名仅作为兼容实现细节。前端只读取是否已有 Key。留空保留现有凭据，切换端点时沿用现有密钥与端点绑定保护。连接测试使用固定的虚构样例。
- 「保存模型配置」先用候选地址、模型和密钥实际请求固定 `Hello, world.`；验证成功后才原子写入配置与凭据。失败时保留表单内容，不覆盖已保存配置、Key 或 revision。目标语言与缓存管理在模型配置未保存时禁用。
- 模型访问由原生端统一完成，按能力校验请求与响应。翻译仍用现有分段与缓存路径；摘要和修复共用连接配置，分别校验结果结构。设置变更要拒收旧配置的迟到响应。保留既有超时、响应体上限和日志脱敏，网页演示只有模拟数据。
- 写信聊天使用 [assistant-ui 官方组件](https://www.assistant-ui.com/components) 及 ExternalStoreRuntime，复用草稿会话与 Tauri 模型命令。

## 邮件摘要

- 阅读工具栏在翻译旁放摘要入口。对话模式绑定被点击的单封，外部邮件窗口复用相同展示。无配置时提供设置入口，正文未就绪时由现有加载状态控制。
- 正文右上角复用悬浮区。生成、失败、结果、收起共用锚点，保留正文尺寸和滚动位置。结果支持复制、收起、关闭，失败可重试，生成可取消。窄区限制卡宽和高度，内容可滚动。邮件切换或窗口销毁后丢弃旧结果。
- 输入只取当前正文的有界文本，忽略邮件中的指令，响应按结论、要点、可选时间字段验证并安全渲染。原文没有明确时间时省略，仅显示模型从邮件得到的信息。附件和外链留在此次输入和输出之外。明确、可执行的时间提醒随摘要在同一请求中生成，引用原文核验后展示，日历图标打开预填事项。
- 摘要语言跟随翻译偏好中保存的目标语言。首期按邮件身份、正文指纹、目标语言、模型配置版本和摘要模板版本在应用会话内复用结果，缓存版本为 `summary-v3`；应用退出后清除。独立持久缓存可随后评估存储、删除和失效要求。原始 MIME、阅读缓存与标记沿用现有路径。

## 写信修复

1. 从富文本工具栏打开「AI 助手」。宽窗口在整个写信框的右侧展开独立面板，窄窗口面板从右侧覆盖。快捷指令放在聊天输入框上方，可继续输入自由指令。首期范围为当前可编辑正文，允许用一句意图生成空白草稿；主题、地址、签名、引用和附件保持原有编辑路径。
2. 首次指令以当前草稿正文为基准，后续指令可迭代当前未应用建议。每次展示相对当前草稿的最终净变化。响应先完成结构校验，再展示差异；低兼容模型允许提交后一次返回。中止支持保留上一版建议，结束或失败提供反馈。聊天状态绑定当前草稿窗口，首期仅留在会话中。
3. 编辑器在受影响段落位置展示删除线与新增高亮，搭配 ＋／− 标记。用 Tiptap/ProseMirror 装饰与只读预览承载 Diff。模型只返回有界文本替换及提案说明，应用时核对草稿 ID、编辑模式、版本和段落映射。未受影响的段落、格式及内嵌对象不应被重写；跨越图片、表格或无法可靠定位的建议拒绝直接应用，引导用户缩小修改范围。
4. 「应用到正文」通过一次编辑器事务合入，进入已有自动保存，支持一次 Cmd/Ctrl+Z 撤销。「舍弃」清除提案。聊天期间用户可以继续编辑；草稿有变化时旧提案标过期，需基于最新版本重新生成。发送、定时、关闭、草稿切换及图片准备期间复用现有写信状态保护；临时建议与预览标记不进入保存和发送路径。
5. 富文本正文先交付。纯文本模式可以复用文本 Diff；HTML/Markdown 源码模式及快速回复列作后续单独验收。评审原型使用虚构草稿、预设示例响应及简化的只读预览层，源码模式、空白生成、失败与过期主要由此 PRD 描述。

## 验收条件

- 旧翻译配置保存、读回、端点更换、清空密钥和真实翻译回归。两份 locale 同步，模型配置版本切换时旧请求不可更新页面。
- 单封、对话、外部窗口核对摘要归属，覆盖取消、超时、错误重试、迅速切信、明暗配色、窄窗口和正文滚动稳定。
- 写信覆盖多轮与停止、应用/舍弃/一次撤销、输入法回车、过期结果、切换草稿、发送和关闭；核对草稿保存与发送内容中不存在差异标记，已有格式、图片节点、签名和引用可正常使用。
- 对实际实现执行 `npm run check:ui`、`npm run check:i18n`、相关前端与 Rust 测试及 `npm run build`。macOS 和 Windows 原生验证单独记录。评审通过后先实现模型配置兼容，再交付阅读摘要与写信修复。

## 写信助手故障修正（2026-11-14）

- assistant-ui 未完成消息的默认网页文字组件会追加一个 `●`。写信助手现在只组合官方 `MessagePrimitive.Parts` 与 `MessagePartPrimitive.Text`，运行态由应用单独显示一个旋转图标和“正在修改…”，不再出现重复黑点。
- 真实 DeepSeek 返回的修复计划把段落文本写在 `replacement`，应用原协议只接受 `text`，导致连接和模型配置均正常却提示格式失败。修复请求现在与翻译共用 DeepSeek 非思考、JSON 输出和输出上限参数，提示明确指定 `index` 与 `text`，解析器兼容 `replacement`，原有索引、行数、长度及字符校验保持。
- `mailAiError` 不再吞掉后端原因，配置变化、取消、超时、连接、TLS/代理、读取中断、格式、截断、响应过大、凭据、HTTP 401/402/403/404/429/5xx 分别使用双语反馈；无法识别时才显示通用失败提示。
- 原生开发实例使用虚构草稿实测运行态无黑点，DeepSeek 实际返回英文改写并展示正文 Diff；建议随后舍弃，未发送邮件。前端 496 项、Rust 461 项、生产构建和格式检查通过，其他服务与 Windows 未验证。
