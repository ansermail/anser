# Issue #3：EML 邮件导入方案

日期：2026-10-23。状态：用户已于 2026-10-23 确认按方案实施，第一阶段开发、自动化及本机原生验收完成；未合并或发布。用户已于 2026-10-24 明确取消 IMAP 服务器导入，本功能最终范围仅为本地存档导入。

需求来源：[Issue #3「feat: 邮件导入功能」](https://github.com/ansermail/anser/issues/3)。2026-10-23 实时读取：支持标准 `.eml` 导入，提出导入到指定账号、文件夹的设想；暂无评论。下面的默认值和分期属于本方案建议，尚非 issue 作者确认的要求。

## 1. 建议范围

第一阶段支持：选择一个或多个 `.eml` 文件，导入到指定现有账号下的本地分类文件夹。文件完整复制进当前存档位置，随后可以离线阅读、搜索、查看附件、参与对话和备份。选择账号表示本地归属，不表示上传到该邮箱服务器。

原第二阶段提出的 IMAP 服务器导入已由用户于 2026-10-24 明确取消，不保留为待办或后续阶段。不实现服务器 APPEND 上传、远端文件夹导入或服务器同步；本地分类不得显示成 INBOX 等服务器目录，也不能宣称支持服务器导入。

首阶段不包含 PST/MBOX/ZIP、递归扫描目录、拖放任意系统文件、无账号的独立本地邮箱，也不自动从 EML 邮件头判断目标账号。IMAP/POP3 账号均可作为本地归属，账号离线或停用不影响本地导入；必须仍存在，且存档位置可写。

## 3. 用户操作与默认行为

1. 设置 → 本地存档 → 现有存档卡片中点击“导入邮件”。
2. 原生文件对话框多选 `.eml`，大小写扩展名均接受；扩展名和内容均需校验。
3. 在导入弹窗选择“归属账号”和“本地文件夹”：可选现有分类，或输入新分类名称，默认“导入邮件”。目录为当前既有的平面本地分类，不增加服务器路径层级语义。若没有账号，提示先添加邮箱。
4. 展示文件数、原始文件总大小、目标账号与分类，明确“仅保存在本机，不会上传到邮箱服务器”；此时只做有界元数据检查，不修改存档或邮件。
5. 开始后后台逐封处理，显示“已处理 / 总数”与新增、补全、重复、失败数量。弹窗可收起，任务继续；在既有后台任务分类查看状态并取消。原生选择或预检查期间关闭弹窗、切换目标，废弃迟到结果；任务启动后目标固定，普通页面导航不改变目标。
6. 完成后提供“查看导入邮件”和失败明细。查看入口按账号与本地分类导航；补全的旧邮件保留原分类，结果中明确提示。批次明细只在本机展示必要文件名与固定错误类别，不写入公开日志。

使用现有 shadcn `Dialog`、`Select`、`Input`、`Field`、`Progress`、`ScrollArea`、`Alert`、`Badge` 和 `Button`；文案统一加入中英文 JSON。公开 Pages/演示仅使用虚构任务，不开放真实文件读取。

建议默认规则：

- 新增邮件默认已读、不加星、不发送新邮件系统通知，避免历史导入扩大未读数字。后续可通过现有操作标为未读。
- 不自动执行收件规则，不自动补发、不触发 SMTP/APPEND/COPY/MOVE；用户后续主动运行规则时沿用现有来源保护。
- EML 原始日期、Message-ID、引用链、正文和附件原字节保留；无效/缺失日期保持未知并按既有规则置后，导入时间单独记录，不能冒充邮件日期。
- 导入邮件可使用现有阅读、打印、搜索、回复/转发和本地删除；回复/转发仍只开草稿。纯本地邮件的服务器移动/删除等入口不可用，不虚构服务器身份。
- 系统双击 EML 继续只读打开，不自动导入。已有“应用内不展示打开 EML 按钮”的约定不变，新增的是明确的持久导入操作。

## 4. 重复、补全与冲突

沿用数据库 `UNIQUE(account_id, hash)`；hash 为完整原始文件 SHA-256。

| 情况                                 | 处理                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------- |
| 同一账号、相同字节，已有完整原件     | 计为重复，保留原 ID、已读、星标、分类和废纸篓状态，不移动到本次目标分类             |
| 同一账号、相同 hash，已有仅在线记录  | 校验并保存完整原件，补全派生内容，保留原 ID、原日期、用户标记和分类；单列“补全”结果 |
| 不同账号、相同字节                   | 每个账号保留各自邮件记录；物理原件可按现有 hash 共享                                |
| 相同 Message-ID、不同原始字节        | 分别保存，不按主题或 Message-ID 吞掉差异版本；对话仍走现有引用图                    |
| 重复记录在本地废纸篓                 | 跳过并提示，不隐式恢复、不新建替代记录                                              |
| 同一批次重复选择、文件改名后再次导入 | 按实际字节处理，不靠文件名去重                                                      |

不要做“自动覆盖旧邮件”或“自动移动已有分类”。若用户需要改分类，走现有显式操作。

## 5. 后端数据与提交设计

建议新增 `src-tauri/src/eml_imports.rs`，负责作业、取消、校验和短事务发布；共享 EML 读取校验可抽到独立小模块，避免把只读文档的会话 token 变成导入任务。

数据分两部分：

- `message_imports`：持久本地导入来源，记录 mail_id、hash、首次导入时间。它不是服务器 `sources`，没有 UID/UIDVALIDITY。用于明确来源及恢复后保留语义；不持久保存源文件绝对路径。
- `eml_import_jobs` / `eml_import_items`：本地作业与条目、固定目标、revision、逐项状态及固定错误码。必要的源路径仅供本机任务读取，不写活动日志，不输出到前端任务汇总，不随备份分发；完成/取消后清除路径。

逐封处理流程：

1. 核对任务代际、目标账号存在、目标分类有效及取消状态。
2. 有界读取一个普通文件快照，检查邮件头、MIME 结构/解码预算并计算 hash；解析从同一字节快照取得，不在多个阶段重复读到不同版本。源文件移除或读取中变化时拒绝该项；允许继续其他文件。
3. 使用既有存档入口在当前实际存档位置准备原件，校验散列。读取、完整写入和解析在 SQLite 写事务之外。
4. 在短事务中再次核对代际、账号、目标及去重状态，发布完整原件，写入/补全 `messages`、导入来源和逐项完成状态，让现有索引/对话版本机制同事务更新。沿用 `archive_gate` 和位置锁的既有顺序，同删除/迁移互斥。
5. 事务提交后发变更事件，前端合并刷新邮件、统计、分类、任务与活动区；刷新节流，避免每封强制重载。当前列表按版本重置，不能把旧游标页拼入导入后的版本。

文件发布和 SQLite 不能构成跨介质事务：数据库提交失败不得留下“导入成功”状态；发布后崩溃可能留下未引用原件。按现有完整性/引用核对机制处理这类孤立原件，不能在错误回滚时直接删除可能已被其他账号引用的同 hash 文件。

建议新 IPC：预检查、启动、读取任务状态、取消、清理已完成任务。前端只拿任务 ID/结构化结果，不通过 JS 传递整封 MIME；原生对话框及主窗口 capability、预览静态桥一起核对。

## 6. 有界执行、取消与恢复

- 建议首版上限：单封 64 MiB（与已有 EML 预览一致）、单批 1,000 个文件且原始文件总量不超过 1 GiB。属于待压测调整的产品参数，不宣称现有导入已支持这些规模。
- 后端以 1 个文件工作单元顺序执行，I/O/解析进入阻塞工作池，不持有长数据库事务或整个批次的全局锁；不一次将全批 MIME 载入内存。MIME 深度、部件数、解码累计量与工作耗时也需设上限，文件大小限制本身不够。
- 预算检查从校验后的真实存档路径获取可用空间，考虑未持有原件及临时写入空间并预留余量。预检查只给估计，提交仍处理磁盘满/断盘错误；外置盘不可用时停止任务，不回落默认目录。
- 单个损坏/超限/无权限文件计失败后继续；磁盘满、存档身份失效等全局问题停止待处理项并给恢复入口。
- 取消在逐封发布前核对 revision；取消确认后无新邮件提交，已完成邮件保留。取消与正在进行的短提交按确定顺序串行化，结果计数应反映已提交部分。
- 退出后将运行任务标为“已中断”，保留逐项结果；不在下次启动时无提示重读旧路径。用户主动重新选择未完成文件后，依靠 hash 去重继续导入。
- 目标账号移除时取消该任务；已经导入的完整本地邮件继续保留。修改账号在线保存偏好不能把显式导入降为仅在线记录。

## 7. 与现有数据生命周期的集成

- 导入不伪造可信远端来源；纯本地记录只出现在全部邮件、本地存档、账号范围和本地分类，不出现在服务器目录或其聚合计数。
- 核对已读/星标、服务器保留策略及规则任务：无远端来源时不排入远端同步；后续实际收取同 hash 时才关联真实来源，不覆盖导入后用户意图，也不删除导入原件。
- 存档迁移、完整性检查与手动本地删除沿用既有机制；存档清理必须正确处理纯本地来源，不能生成无法再下载的仅在线空壳。永久清理引用时同步清理导入来源元数据。
- 备份保留邮件与持久导入来源，剔除可执行导入任务、源路径及临时文件；恢复不启动导入，不依赖原 EML 路径。现有 `restore` 只挑选部分表恢复，必须显式补充新来源表恢复与旧格式兼容，不能仅依赖数据库快照包含了新表。
- 无账号备份恢复、账号移除后，已保存邮件继续可在全局/本地存档找到，不依赖账号列表存在才能阅读。

## 8. 实现顺序与验收

1. 后端闭环：共享有界读取、专用提交入口、来源及任务迁移；先用临时存储完成单封/重复/补全及失败一致性回归。
2. 界面闭环：同卡片入口、目标选择、后台进度与取消、结果导航、中英文及演示隔离。
3. 生命周期回归：备份恢复、账号移除、外置盘/迁移互斥、索引/对话分页、规则及远端同步保护；再验原生文件选择和实际阅读。

关键验收矩阵：

- 中文/英文、纯文本/HTML、multipart/alternative、内嵌 CID 图、同名附件及附件原字节；日期时区、无日期、引用链与差异版本不丢失。
- 多选、重复批次、跨账号共享、已在线同 hash 补全、废纸篓重复和分类冲突；重启后可读且结果计数准确。
- 假 EML、损坏编码/结构、超限文件、符号链接/特殊文件边界、源文件变化、MIME 预算超限，均有确定结果；允许的可恢复解析警告保留原件并展示警告，不虚报完全解析成功。
- 取消/旧代际、账号移除、写盘/数据库失败、发布前后崩溃及重启，不产生错误成功状态、不删除共享文件。
- 外置盘断开不写回默认目录；备份恢复不携带执行中的导入任务、不依赖源文件。
- 无网络也可导入；不发送 SMTP/APPEND/COPY/MOVE、不自动运行规则、不弹新邮件通知；新增默认已读，同步未读口径不变。
- 导入中可继续阅读/写信；1,000 个小文件的批次验证后台执行、分页刷新、内存和 UI 响应，不把未测耗时当性能承诺。

开发后执行 `npm run check:ui`、`npm run check:i18n`、相关前端交互测试、`npm run build`、`npm run build:preview`、相关 Rust 回归及 `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`，并用 `npm run desktop` 验收原生选择/取消/阅读。新增 IPC/权限或桌面脚本时覆盖相应检查。发布另走全量门槛，单独记录代码、自动化、原生验收、云端和发行结果。
