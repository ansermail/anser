# 附加存档工作点（2026-11-04）

## 目标

按截图补齐“附加存档”能力：把超过保留期的完整原始邮件移到可断开的外置目录，账号和近期邮件继续使用本机索引；外置盘未连接时不回退本机，打开旧邮件明确提示连接原磁盘；提供立即归档、取回本地、规范目录、更改目录、最近记录和独立 `index.html` 检索页。

本轮不改版本号、不创建标签、不发布；补丁只提交到本地 `main`，不推送。公开 latest 仍是 0.1.36。

## 已实现

### 配置与数据

- 应用数据根保存 `archive-tier.json`：外置目录、是否同一存档的标识和保留天数。
- 外置目录写入 `.anser-tier-store` 标识；路径不可达或标识不匹配时明确报错，不把外置原件误当成本机文件。
- 新增 SQLite 表：
  - `archive_tier`：原文哈希、年/月相对路径、邮件日期、主题、发件人、大小和归档时间。
  - `archive_tier_restored`：用户主动取回本地的哈希，自动归档跳过这些邮件。
  - `archive_tier_log`：最近归档、取回和规范目录记录，最多读取 50 条。
- 外置文件按邮件实际日期保存为 `YYYY/MM/<sha256>.eml`。日期无法解析时放在 `unsorted/unknown`，不按下载时间猜测。
- 同一封 MIME 被多个账号引用时只迁移一次；删除时仍按所有本地保存引用判断是否可移除。

### 归档与取回

- 候选邮件按 `search_documents.instant`（原始邮件日期）计算，早于保留天数才进入自动归档；未知日期和已取回邮件不自动处理。
- 先读取并核对本机 SHA-256，再原子复制到外置目录并再次核对；成功后写入索引并移除本机副本。复制失败、目标同名冲突或本机原件变化时不移除本机文件。
- 取回先复制并核对本机副本，再在事务中移除外置索引、记录取回状态并删除外置文件；事务失败不会丢失外置记录。
- 手动“立即归档”会处理超过保留期的邮件，包括之前取回的邮件；自动任务跳过取回记录。
- 同一存档根只允许一个后台任务；归档、取回和规范目录串行执行。
- 启动后延迟执行一次自动归档，之后每 6 小时检查；需要外置盘可用。

### 读取回退

- `archive::read_raw` 先读本机原件；本机不存在时才读取附加存档，并再次核对 SHA-256。
- 本机文件存在但损坏时直接报错，不回退外置同名文件。
- 外置盘未连接时，近期本机邮件仍可读取；旧邮件返回“附加存档盘未连接或目录不可用”的明确错误。
- 备份、规则、附件预览、邮件详情、导出及已有 `archive::read_raw` 路径自动使用同一回退。
- 本机的“存档位置迁移”允许已被附加存档接管的哈希，不再把外置旧邮件误报为本机原件缺失。

### 删除与回滚

- 删除本地存档或本地文件夹时，同时暂存本机原件和附加存档原件；数据库事务提交后才删除暂存文件。
- 事务失败或进程中断时，仍被索引引用的暂存文件恢复到原位置；已提交的删除在下次启动继续清理暂存目录。
- 外置盘未连接且要删除的原件在附加存档中时，删除会被拒绝，索引、账号存储设置和原件保持不变。
- 同一哈希仍被其他账号完整保存时不会移除本机或外置原件。

### 规范目录与索引

- “规范目录”递归扫描外置目录中的有效 `.eml`，按索引中的邮件日期复制/校验到 `YYYY/MM/<hash>.eml`，再移除旧位置并更新索引。
- 外置根目录生成独立 `index.html`：按邮件日期倒序、暗色适配、按主题/发件人即时筛选，链接直接指向相对 `.eml` 文件；不依赖应用运行。
- 主题、发件人等元数据在 HTML 中转义。索引按需重建，并在配置、归档、取回和规范目录完成后更新。

### 校验与界面

- 快速校验先检查本机文件；本机没有时检查附加存档文件存在、普通文件和大小。深度校验读取本机或外置原件，核对 SHA-256、MIME 和附件解码。
- 外置盘连接时，校验覆盖本机与附加存档的全部完整邮件；外置盘断开时明确标为未完成，不用旧成功结果冒充。
- 设置页“本地存档”下新增“附加存档”卡片：外置原件数量/大小、待归档数量/大小、保留天数、路径、连接状态、打开存档、立即归档、取回本地、规范目录、更改目录和最近记录。
- 保留天数使用 shadcn Select；确认使用现有 AlertDialog；最近记录默认折叠并显示操作、数量、大小和时间。
- 界面文案已同步 `src/locales/zh-CN.json` 与 `src/locales/en.json`。

## 未验证或限制

- 没有截图规模的 63,914 封 / 13.7 GB 真实副本；本轮只有 5,499 封 / 464 MB。不能宣称 6.4 万封规模已验收。
- 原生设置页只验证了配置、保留天数、确认框、断盘/恢复及按钮状态；实际归档进度、取消、取回和规范目录尚未在原生界面用有数据的副本走完整流程。
- Windows 实机、外置盘热插拔、磁盘满、权限拒绝、强制退出后的多阶段恢复尚未验收。
- 已有外置原件时，“更改目录”只接受原存档目录或标识匹配的目录；换到全新空盘需先“取回本地”。本轮未实现后台搬运到新盘。
- 未知日期邮件不会自动归档，避免按下载时间猜测。
- `index.html` 为全量单页；6.4 万封的实际浏览器内存和打开时间未测。
- 自动调度只验证了逻辑入口，未做 6 小时真实等待测试。
- 附加存档文件没有额外应用层加密，外置盘本身的访问控制由用户负责。
