# 前端开发规范

本文件覆盖 React / TypeScript 前端架构、国际化、邮件正文隔离渲染、打印排版、Tiptap 写信画布、状态并发保护与 Web 预览边界。

## 1. 国际化（i18n）

- **集中配置**：界面提供简体中文 / English 切换，全部固定文案与语言选项集中在 `src/locales/` 的 JSON 文件中；新增或修改文案须同步更新两份语言文件及插值参数，禁止在业务组件中维护两套界面或手工拼接译文。修改后必须运行 `pnpm check:i18n`。
- **持久化与隔离边界**：
  - 切换语言保留当前导航位置、草稿与未保存输入；语言偏好独立持久化，其他偏好保存不得覆盖。
  - 应用界面语言与邮件模型翻译目标语言相互独立。
  - 仅本地化固定界面文案、原生菜单与系统通知提示，不得翻译或改写用户邮件内容、服务器路径、协议身份、原始邮件或已有活动日志。
  - 日期与日历显示区域跟随当前界面语言，实际时间点与时区范围语义保持不变。

## 2. 邮件正文隔离渲染与深色适配

- **隔离 iframe 与主题同步**：邮件正文位于禁用脚本的隔离 `iframe`，接收应用解析后的明暗模式和当前配色。根节点的明暗类与配色属性在订阅通知前同步应用，正文 layout effect 在读取 `--background` 前也会应用当前外观。只切换深色预设时，中性底色同样更新。
- **深色适配策略**：深色中性底色直接复用应用 `--background`（与上方邮件信息栏一致）；仅适配中性底色、文字（含略带色相的近黑文字）与链接，保留作者饱和色、彩色底面、背景图、正文图片及局部品牌图的原浅色背板。提供单封“使用原始浅色配色 / 跟随应用主题”入口，仅影响阅读显示，不改变应用主题、MIME 原件、打印或转发内容。
- **HTML 净化与排版**：邮件 HTML 与签名继续安全净化并隔离渲染，严禁跨文档执行邮件脚本。默认长文本换行保留表格单词固有最小宽度，不得全局使用 `overflow-wrap: anywhere` 把表头压成逐字竖排；邮件自身样式优先，排版修复不改写 MIME 原件。只读正文区域允许浏览器原生“检查元素”调试（写信/签名沿用既有菜单边界），但不得为调试放开邮件脚本、净化或 CSP。
- **安全外链导航**：桌面界面外部链接统一通过 `open_mail_link` 系统浏览器入口打开，不依赖 WebView `target="_blank"`，打开失败需反馈；网页端保持正常链接行为。禁用脚本 `iframe` 中的安全外链原生跳转须避开 `frame-src` 对子帧导航的拦截，由 Tauri 导航钩子取消并交给系统浏览器或写信窗口；修改沙箱、CSP 或链接路由后须实测原生点击，不能以 HTML 生成测试代替。
- **CSS / 字体与图片 CSP 隔离**：邮件样式表（`stylesheet` / `@import` / `@font-face`）与字体文件属于独立 CSP 资源类型，原生通道复用全局代理并按实际类型、容量与期限校验；外部 CSS 的相对资源按最终响应 URL 解析，不得误送图片通道；邮件选择器严格限定在正文/打印独立样式边界内，不污染应用主页面，不为字体开放脚本或任意顶层导航。
- **WebKit 禁用脚本约束与图片诊断**：WebKit 原生脚本禁用正文不绑定子文档资源/外链事件回调，改用父页面状态检查与原生导航，避免重复 sandbox 警告。正文图片失败/超时除页面胶囊提示与重试外，须在控制台打印诊断（每图只打一次，URL / `srcset` / `alt` 全部 URL 编码，`data:` 内联图仅记录长度，诊断核对 `GET` 实际解码内容，不以 `HEAD` 或 MIME 声明替代）。

## 3. 单封邮件打印

- **内容边界**：打印仅针对当前阅读单封邮件，从安全净化后的正文与文字化邮件头/附件名称生成；禁止将原始 HTML 插入应用页面、执行邮件脚本或把侧栏/列表一并打印；打印不修改原件、已读或星标状态。
- **样式保真与分页**：保留完整净化文档的 `head` 样式、`html/body` 属性、作者字体/字号/配色、表格与段落间距，在独立样式边界（Shadow DOM）内排版，禁止删除样式后套用应用 CSS reset。自定义字体仅以私有族名临时注册，不得覆盖应用字体。打印默认浅色正文并保留作者背景与品牌色，长邮件必须完整分页，不以截图或定高 `iframe` 截断。
- **页面参数与 macOS `NSPrintInfo`**：默认 A4 纵向、100% 比例、`16mm` 页边距、从页顶排版；超宽正文可适配可打印宽度，不得把整封长邮件缩成一页。原生打印时须解除应用外层 `html/body` 固定高度与 `overflow` 裁切（含外部邮件窗口）。macOS 每次使用独立 `NSPrintInfo`（不改共享打印偏好、不继承旧缩放/居中），且 `WKWebView` 初始 `NSPrintInfo` 页边距必须与 CSS `@page` 一致（原生与 CSS 边距不叠加，初始化为 `0` 会导致首次分页与最终绘制不一致）。
- **权限与本地化**：新增原生 WebView 能力时同步核对 Tauri capability 与打包产物（保留 `core:webview:allow-print`）；macOS 系统打印面板语言随应用包 `Info.plist` 声明选择，正式包 `src-tauri/Info.plist` 与开发预览 `scripts/mac-dev-runner.mjs` 均须声明简体中文。修改打印布局后运行 `pnpm build && pnpm test:mac-print` 并实测系统打印面板。

## 4. 写信编辑器（Tiptap / Markdown / 草稿）

- **格式与扩展**：完整写信新草稿默认富文本，恢复旧草稿保留原格式，简短对话回复可保持纯文本。使用官方 Tiptap / ProseMirror 开源扩展，富文本与 Markdown 所见即所得共用 Tiptap 画布。字体选择同时提供中文及常用英文字体，保存完整 CSS `font-family` 与回退链（不自动下载或嵌入字体文件）。字体颜色预设与“默认颜色”按选区应用并随草稿/邮件 HTML 保存；保存与预览前将 CSSOM 返回的 `rgb()/rgba()` 归一化为十六进制（半透明保留 `rgba`），兼容 Outlook 等客户端。
- **排版同源与预览一致性**：富文本与 Markdown 可视化画布与投递 HTML 共用字号、间距、代码、引用与表格配色等排版默认值；发送预览直接渲染发送队列、定时提交使用的同一份 `prepareCompose` 结果与 `deliveryHtml`，预览阶段不另加额外段落间距或正文转换；即时与定时提交均将当时预览的明暗配色内联到邮件正文。纯文本签名进入 HTML 邮件保留逐行换行与紧凑行距（使用保留空白的文本节点或等价结构，不拆为带默认外边距的 `<p>`）；空富文本正文在首次输入前也不退回逐行 `<p>`，无正文时签名顶齐、有正文后保留 `18px` 间距。从纯文本切换 HTML 签名时转义文字并保留换行，同一账号本次编辑的两种格式分别保留。
- **表格宽高与拖拽**：表格与单元格调整后的宽高以投递 HTML 内联样式保存，合并单元格保留各逻辑列宽；Markdown 源码对 GFM 无法表达的表格与草稿内嵌图使用净化后的 HTML，切视图/重开草稿/投递均保留。编辑区与预览表格保持四角圆角与单线内网格；列分隔线以鼠标按下位置判断（Pointer Events），双向拖拽调整相邻两列保总宽，最右边框缩放整表尽量保列比例，单次拖拽以一个 ProseMirror 事务保存；列宽基于渲染单元格边界与 `TableMap` 逻辑列计算，不得依赖 WebKit `<col>` 元素边界。表格拖拽提示线、空正文占位、查找装饰与 AI 修复 Diff 装饰均属编辑期装饰，严禁进入草稿、预览或 MIME。
- **任务列表与正文图片**：任务复选框与文字首行对齐，发送预览与投递转为同排静态勾选符号并随编辑实时更新。富文本正文图片作为整体图片节点选择（禁用图片内部 WebKit 识字选区，保留右键尺寸菜单，不得对整个编辑器禁选文字）。正文内嵌图片使用草稿自有内容快照及既有 `cid` MIME 入口（有界读取 + 字节识别位图，不依赖源文件或云上传），准备过程核对窗口租约与发送状态，迟到结果丢弃，未准备完成禁止发送或关闭。
- **草稿、附件拖拽与数据独立性**：
  - 保留正文、签名、引用原文的独立编辑/草稿数据，最终发送组合不重复追加；切换发件身份重新核对签名与 SMTP 身份。
  - 空白新邮件不自动保存、关闭直接舍弃（默认发件账号与自动签名不计用户输入）；填写收件人/主题/正文、加附件或存在回复/引用上下文时保留草稿。关闭、发送/定时提交与自动保存按顺序串行，防止迟到保存重建已舍弃草稿；保存或清理失败保留编辑窗口并反馈。
  - 保存/舍弃/发送/定时提交结束后刷新可见草稿列表（含请求代际保护，防旧结果恢复已提交卡片）；写信表单布局样式仅作用于外层容器，不用后代 `fieldset` 选择器覆盖嵌套 shadcn `FieldSet`。
  - 草稿箱清空确认数量并以确认时本地草稿快照为范围，整批核对后事务删除（内容变化、编辑租约或已进入发送记录时拒绝，不删用户原文件或服务器草稿）。
  - 文件选择与原生拖拽复用去重/错误反馈，异步返回核对草稿 ID 与编辑状态；拖拽仅接受当前写信窗口范围、物理坐标按像素比换算，发送/关闭/倒计时期间忽略并在生命周期结束解绑。

## 5. 前端交互、状态并发与工作台前端逻辑

- **快捷键保护**：邮件快捷键复用现有操作与来源保护，回复/转发仅开草稿，已读/星标仅改当前阅读邮件（不隐式扩大到对话或多选）。输入/编辑/IME/弹层/菜单、已处理事件、长按重复、正文切换及范围变化的旧结果不接管；异步标记未结束时不重复提交，写信中不以新建快捷键替换未完成草稿。
- **通知点击与对话定位**：新邮件通知点击直达绑定单封邮件（启动前排队、写信保留草稿、迟到结果不覆盖后续导航，仅核对绑定本机邮件 ID/账号/可信来源，不按标题/UID 猜，仅标目标已读）；重复点击重新定位目标单封开头；对话打开先定位选中单封开头，先前邮件异步加载不得挤走位置，用户主动滚动后不抢回。
- **搜索防抖与结果提示**：搜索防抖仅在搜索值实际变化时发新查询；启动空搜索或同值回调保留查询身份，不得误取消通知定位、分页或阅读请求（异步回归测试须明确跨越初始防抖期限）。保留此前阅读内容时，仅在当前查询稳定且结果确认空后才提示其不在搜索结果中，不按当前分页推断归属。
- **规则快照（前端协同）**：规则条件中已读/星标以首次命中快照为准，同一规则多步动作可“未读 → 标记已读 → 归类”完整执行；用户手动修改过的本地字段按既有意图保护提示不被覆盖。
- **工作台前端机制**：
  - 四象限拖拽与状态看板跨列拖动统一使用 **Pointer Events**（以胶囊左侧圆点为视觉锚点，保持按下相对偏移，禁用会被桌面 WebView 原生拖放接管的 HTML5 `dragstart/drop`），放下后按事项版本保护持久保存；分组看板仅允许在同组可见列之间移动，同时保留右键菜单与状态下拉作为非拖拽入口。
  - 工作台事项右键删除在全视图复用按 `ID / revision` 的删除确认与失败反馈，跨日多入口指向同一事项并删整条记录；右键菜单与确认不得触发日期选择、编辑或拖动，取消保留数据。
  - 事项列表读取时由 SQL 联表生成只读 `mailSubject`（不写回事项 JSON）；旧工作记录中的预计/实际工时属性由初始化迁移清除。

## 6. Web 预览（`/demo/`）与演示模式边界

- `/demo/` 与桌面端共用 App 与业务组件，禁止单独维护仿制界面；正式原生包隐藏示例入口，开发预览保留。
- 预览构建必须将原生模块替换为不可调用的静态桥，使用隔离内存虚构数据，禁止读取既有邮箱持久数据、调用原生图片入口、读写系统默认应用、连接真实模型/保存 Key 或执行真实连接/收发/文件导入。
- 演示模式中剪贴板同时含文字与图片文件时优先保留文字粘贴；单独粘贴或拖入正文图片时明确说明演示模式图片限制。
- Pages 预览构建检查（`pnpm build:preview`）须覆盖布局样式与原生 IPC 隔离。
