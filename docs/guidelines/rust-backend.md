# Rust 后端、存档与邮件协议规范

本文件沉淀 `src-tauri/src/` 下的原始 MIME 存档、分层存储、SQLite 事务、IMAP/POP3/SMTP 协议、全局代理、规则引擎、本地导入与系统原生集成红线。

## 1. 原始 MIME 存档与分层存储

- **MIME 原件不可变**：完整原始 MIME 是存档原件，附件必须保留原始字节。解析/显示修复只能修改派生索引，严禁改写原件、将原日期替换为下载时间，或丢失已有邮件 ID、标记、分类及来源。
- **在线阅读过期缓存（`read-cache/`）**：仅用于加速在线阅读的远程正文与附件读取；不得混入 `archive/`、不得改变 `savedLocally`、不得计入完整存档统计、备份或完整性校验。缓存键须核对邮件身份与原件哈希，完整原件始终优先；过期、超容量、身份变化或校验失败时丢弃缓存并重读；保留期按最后打开时间计算，关闭缓存后每次重新访问服务器。
- **账号与存档独立**：完整本地存档独立于账号与服务器留存；移除账号或服务端来源消失不得自动删除原件。本地删除、服务器移动/删除与永久清理必须明确区分并保留确认与恢复边界。
- **存档位置管理**：统一通过 `archive_location` 与 `archive` 读写入口访问，严禁在新代码中硬编码默认 `archive/` 路径。外置路径只迁移完整原件，账号、SQLite 索引与配置留在应用数据根；须校验复制后再切换位置，迁移与保存/删除互斥；断盘或目录标识不匹配时明确报错，不得自动回落到本机或把未保存邮件标成已完整保存。
- **附加存档（外置分层）**：
  - 仅迁移超过保留期的完整原件，保留期按原始邮件日期计算（未知日期不按下载时间猜测）；不得迁移在线元数据、草稿或未完整保存内容。
  - 迁移须先复制并核对 SHA-256，成功后才移除本机副本；同一哈希被多个账号引用时只迁移一次。
  - 外置目录使用独立标识文件；外置盘断开时账号、列表与本机近期邮件仍可用；本机原件不存在才读外置层，本机文件损坏不得回退同名外置文件；读旧邮件提示连接原盘，不自动拷回本机。
  - 删除本机存档或本地文件夹时同步处理附加存档原件并保留共享哈希；外置原件先入可恢复暂存，SQLite 提交后才删除，失败或中断恢复仍被索引引用的文件；外置盘未连且待删原件在外置层时拒绝删除，避免孤立引用。
  - 外置根生成可独立用浏览器打开的 `index.html`（按年/月目录组织，必须转义主题与发件人）；更改外置目录在已有外置原件时只允许选原存档或标识匹配目录（换新盘先取回本地）；备份与快速/深度校验须覆盖附加存档，断盘时校验报告未完成。

## 2. SQLite 与两阶段事务保护

- 保留既有 WAL、busy timeout、事务与迁移机制，统一通过 `Store` 提供的连接入口访问。
- 长网络等待、完整 MIME 写入、散列读取与大文件复制严禁放进 SQLite 长写事务；异步结果发布前重新核对账号、来源与任务代际。
- **完整保存两阶段提交**：先在存档入口准备并校验临时原件，再用短事务重新核对任务代际、配置、来源与内容，原子发布保存状态、分类与规则 cursor；已有用户标记/分类不被旧任务覆盖，保存失败不得继续后续动作。
- **保存预算**：属于只读快照，按表单选择范围核对服务器编号/大小；未知或不完整结果不得算零，跨目录位置不得猜测去重；实际磁盘空间从 `archive_location` 校验后的物理路径读取；取消/关闭/切账号/改范围废弃迟到结果，不自动下载、改标记或保存配置。

## 3. IMAP / POP3 / SMTP 协议与实时收取

- **协议身份保护**：IMAP 服务器路径与 `UID / UIDVALIDITY` 作为协议身份保留，中文名仅用于展示；禁止按相同 UID 或相同主题猜测来源或回复链。缺失 `UIDVALIDITY`、异常目录及回执不完整遵循既有核对/隔离逻辑。
- **失步连接零容忍**：协议解析或连接失败后不得继续复用失步连接；严禁通过删除 MIME 字节、放宽 literal 完整性检查或虚构 `UIDVALIDITY` 来“修复”收取。
- **完整服务器目录发现**：成功仅取决于完整 `LIST` 结果及账号配置核对，不等待额外关闭连接回执；后台保留上次完整缓存，不用部分响应覆盖缓存或复用失败连接。
- **单账号独占单条 INBOX 监听连接**：
  - 每个启用的 IMAP 账号保留一条收件箱监听连接并独占 `INBOX`：连接后补查、推送触发的收取、周期只读复核与定时补查均在该连接完成，不得为收件箱另开会话。
  - 后台全目录收取跳过已被监听的 `INBOX`；手动立即检查等短连接收完收件箱后重启该账号监听，让服务端新邮件通知重新落到长期会话。
- **轻量检查与 IDLE 验收边界**：
  - 实时连接的轻量检查不能只把 `NOOP` 成功当作目录已刷新；须周期性只读复核 `INBOX` 的 `EXISTS / UIDNEXT / UIDVALIDITY`，防止静默会话或总数不变漏掉新邮件；首次/重复快照不重复触发，复核失败废弃连接，保留有界期限与独立定时兜底。
  - `IDLE` 主动推送、只读复核发现变化与定时补查三者分别记录，后两者不得冒充即时推送验收；保活重发周期与新邮件推送延迟分别说明；协议诊断不输出真实邮件、原始认证或无界响应，不擅自关闭全局代理来证明直连。
- **中断历史 FETCH**：收件箱新实时通知可中断同账号的只读历史 `FETCH`；中断响应整体丢弃（不发布部分原件、不按部分 UID 清理来源），必须退出整条旧连接（不发 `LOGOUT`、不继续他目录）；下载中断钩子在响应消费结束/错误/展开时移除，绝不作用于 SMTP、`COPY/MOVE` 或其他账号。
- **SMTP 与已发送副本核对**：
  - SMTP 接受仅表示发件服务器已接受；发送或 `COPY/MOVE` 结果未确认时严禁自动重发，使用持久状态与只读核对防重复邮件及误移来源。
  - QQ 的精确 `Mail has saved by smtp!` 回执仅进入有限次新连接只读核对，不直接判核对成功，不得再次 `APPEND` 或重发 SMTP；次数耗尽或配置变化保留人工核对，不猜副本。

## 4. 过滤规则引擎与持久规则链

- **正文/附件三态**：规则正文与附件采用“已知匹配 / 已知不匹配 / 待核对”三态；未知正文或未知附件结构不得当作空正文、无附件或正文否定条件命中。
- **邮件头规则边界**：抄送与优先级规则仅使用已取得原件的邮件头（未知头信息须先完整保存再核对，不按空抄送或普通优先级命中）。抄送取自 `Cc` 且不推断密送；优先级归一为高/普通/低；已接收天数按邮件日期计算完整天数。
- **持久规则链与快照**：有按需读取或保存步骤的规则链须先整体持久化，自有 `COPY/MOVE` 在链完成前不提交。持久规则任务保存首次命中的已读/星标快照（旧任务缺字段时退回当前状态）。暂停/取消、配置及账号/来源变化必须废弃旧代际结果；取消仅撤销自有未提交任务，已提交/结果不明任务继续只读核对；关联链未完成时，规则执行记录的独立重试不得绕过链顺序。

## 5. 全局网络代理

- 全局配置，由代理端自行分流，不为各账号重复维护；覆盖 IMAP/POP3、SMTP、应用内 OAuth 令牌请求及原生邮件正文图片（含 `srcset` 与背景图）、样式表与字体。系统浏览器内的 OAuth 登录页不受应用内代理控制。
- 正文资源入口仅提供受时间、大小与并发限制的响应，不转交邮箱凭据、Cookie 或 Referer，不改写 MIME 原件，不为第三方验证页放开脚本；网页示例不可调用原生资源入口。
- 代理密码只存加密凭据库，TLS 始终校验原邮件服务器名称；“代理失败时直连”仅在发送邮件数据之前的代理连接/握手失败时回退，严禁在结果不明的发件后重试。

## 6. 转发附件、邮件本地导入与外部邮件窗口

- **转发附件管理副本**：基于完整 MIME 快照散列核对后复制为草稿归属的管理文件（严禁以预览缓存或用户下载目录作持久来源）；同名文件独立标识，发送前核对归属/元信息/长度/散列，保留原字节与 MIME 类型。准备租约绑定窗口生命周期，切换/关闭废弃迟到结果，未完成阻止发送、失败不静默跳过；草稿与未确认发送保留引用，计划取消恢复独立归属与勾选；管理副本不进存档备份，清理仅限本应用标识目录，不跟随符号链接或递归删未知文件。
- **邮件本地导入**：
  - 2026-10-24 用户已明确取消 IMAP 服务器导入，最终范围**仅为完整原件写入本地存档与本地分类管理**，不实现服务器 `APPEND`、远端文件夹导入或远端同步。
  - 使用独立持久任务与本地来源记录，不伪造 IMAP `UID/UIDVALIDITY` 或服务器文件夹；按账号及原件 hash 去重，保留原字节，默认已读，不自动跑规则/发通知/上传；不覆盖已有记录的 ID、日期、标记与分类。
  - `EML / EMLX / MSG / MBOX` 导入保留原件字节作为 hash 身份，格式转换仅用于派生读取，导出扩展名与原件格式匹配；MBOX 按封有界索引与读取（任务限制按邮件数计算），不支持变体明确失败，不以丢附件/正文算成功。
  - 取消/账号移除在短提交前核对任务代际并保留已完成部分，重启只报告中断不自动重读源路径；备份保留导入来源但剔除执行任务与源路径；纯本地邮件清理不得留下不可再下载空壳。
  - 删除本地导入文件夹须复用可回滚存档清理与短事务保护，同步删除仅由该目录邮件引用的完整原件、保留其他邮件共享原件，不发服务器删除命令。
- **文件内容指纹禁含 `ctime`**：外部邮件与导入源文件的内容指纹仅使用**设备、inode、大小与 mtime，严禁包含 `ctime`**（macOS 打开文档写入 `com.apple.lastuseddate#PS` 等扩展属性仅改 `ctime` 不改字节，纳入会导致随机 `fileChanged`）；真实内容变化及同大小改写仍须拒绝。
- **外部单封邮件独立窗口**：应用内不展示“打开 EML”按钮；外部 `EML / EMLX / MSG` 通过系统“打开方式”/文件关联进入独立原生阅读窗口（非主窗口 `Dialog`），保持只读、不自动导入账号/数据库/本地存档。保留 macOS 红黄绿窗口按钮，复用阅读页功能，上一封/下一封展示但禁用；回复/转发用当前启用账号并从只读 MIME 快照准备草稿归属附件副本；窗口与令牌一一绑定、关闭清理快照；正文图片/CSS/字体协议仅对受控窗口开放；附件另存不得覆盖原件。

## 7. 系统默认应用与 `mailto:`

- 设置「应用偏好 → 系统默认应用」必须读取系统真实默认状态，仅在用户主动操作后修改；示例与网页预览不读写本机默认应用。
- **macOS**：默认邮件应用由用户点击后通过 `NSWorkspace setDefaultApplicationAtURL:toOpenURLsWithScheme:`（Launch Services）设置 `mailto:`，禁止用 `defaults` 或注册表绕过系统授权；修改后重新读取实际状态核对，系统待处理时不自动重试写入。邮件格式关联开启直接关联雁信（无其他应用下拉），关闭恢复开启前记录的实际默认应用（缺失或目标不可用时提示系统调整，不猜测目标）；正式与稳定开发包同步 `Viewer / Alternate` 类型声明，不主动抢占用户默认应用。
- **Windows**：仅打开系统默认应用设置，严禁写注册表扩展名默认值或 `UserChoice`（详见 [docs/WINDOWS.md](../WINDOWS.md#平台工程约束)）。
- **`mailto:` 唤起**：应用接收冷启动参数、单实例转发与 macOS 打开事件后恢复主窗口，解析 `to / cc / bcc / subject / body` 预填写信；已有内容草稿先确认并保存，格式错误链接给出可见反馈。
